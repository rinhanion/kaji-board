# RDRA で考える

kaji-board の地図は `docs/rdra/` にある。はじめに `docs/rdra/README.md` を読み、4 つの視点(1 価値・2 外部環境・3 境界・4 システム)とファイルの対応をつかむ。

**本人への質問・報告は、すべて日本語で書く。**

## はじめに守ること

- **外側の 2 層(価値・外部環境)は、本人に聞いて書く**。コードからは書けない。Claude の想像で埋めない。分からない所は空けて、問いにして聞く
- だから、この手順はサブエージェントに任せない。本体が本人と話しながら進める(サブエージェントは途中で本人に聞けない)
- 書いた文書は、本人に読んでもらってからマージする

## A. 要件定義(新しい要求を外側から下ろす)

`docs/rdra/<次の番号>-要件定義-<Issue 番号>.md` に、今の地図(1〜4)への**差分**として書く。ひな形は `6-要件定義-35.md` の見出しの並びに合わせる。

1. **今の地図を読む**: `docs/rdra/1〜5` と、対象の Issue を読む。要求が、今の地図のどこ(ねがい・まだかなえていない要求・気づき)から来ているかを見つける
2. **今の姿(As-Is)を聞く**: AskUserQuestion で、1 回に 3 つまで聞く。選択肢は 2〜4 個で、ほかの答えも書けるようにする。聞く型:
   - いま、その人(アクター)はどう動いているか。うまくいった時のきっかけは何か
   - うまくいかない理由は何か(知らない・やり方を知らない・時間が合わない・やる気 など)
   - その人は、いまシステムとつながっているか(ボードを見ているか)。いちばん届く道は何か
3. **ありたい姿(To-Be)を聞く**: お試しで、まず目指すいちばん小さな姿。何が効きそうか
4. **答えを地図の言葉に置き直して見せる**: 要求を 1 段細かくし、システムコンテキストと BUC の差分を短く示す。ここで**要求どうしのぶつかり**(例: 新しい要求と「G 手軽に試したい」)を探し、見つけたら本人に選んでもらう
5. **内側へ下ろす**: BUC のアクティビティのうち、**システムが手伝う所だけ**を UC にする。UC から、情報・状態・条件・バリエーションの差分を出す。変えないものは「変えない」と書く
6. **測り方を書く**: 終わりの条件を、今ある情報で測れるか。測れないなら、何の情報が要るか
7. **気づきを書く**: 下ろす途中で見つけたすきまを、`5-気づき.md` の続きの番号で書く。直さず、扱いだけ決める
8. **README の目次に足す**: 「新しい要求の要件定義」の表に 1 行足す
9. **文書だけの PR にする**: ブランチは `docs/<Issue 番号>-rdra-<短い説明>`。Issue はまだ閉じないので、本文は `Refs #<番号>` にする

## B. 地図を畳む(できあがった機能を 1〜4 に入れる)

要件定義をした機能がマージされたら、その機能の PR の中で、差分の文書を 1〜4 に畳む。

1. 差分の文書の視点ごとの差分を、1〜4 の該当する図と表に入れる。実際にできたもの(API・テーブル・画面)に合わせる。差分の文書と違えば、できたほうを正にする
2. `3-境界.md` の「UC の一覧」に、足した API を書く。`4-システム.md` の「情報モデル」に、足したテーブルを書く
3. `npm run check:rdra` で、地図とコードが合っているかを確かめる(`npm run check` の中でも走る)
4. 差分の文書の先頭に「(地図に畳んだ: #<PR 番号>)」と書き足す。文書は消さない(なぜそう決めたかの記録として残す)

## 判断のしかた(この地図で決めてきたこと)

- **アクターを分けるのは、システムとのかかわり方が違うとき**。暮らしの中の立場(親・子・家族の長)が違っても、システムへの操作が同じなら同じアクターにする
- **状態にするのは、それによってできる UC が変わるもの**。変わらないもの(例: 家事の担当)は、状態ではなく情報にする
- **条件には、家族にとっての決まりだけを入れる**。合言葉の HMAC、20 秒ごとの読み直しのような仕組みのためのルールは入れない
- **業務フローにあっても、システムが手伝わない動きは UC にしない**(例: 親が LINE を手で送る)。BUC のアクティビティにだけ書く
- **同じ UC でも、どの「なぜ」につながるかで意味が変わる**(例: 並べ替えは設定ではなく、何から手をつけるかの計画の手伝い)。画面の置き場所だけで分けない
- **小さく試す**: お試しのあいだは外部システムを増やさず、人の手で代わりにできないかを先に考える。効いたら自動にする

## 機械で確かめていること

`scripts/check-rdra.mjs`(`npm run check` の中で走る)が、次のずれで落ちる。落ちたら、地図を直してから進める。

- `src/index.ts` の API が、`3-境界.md` の「UC の一覧」に無い(または、地図にあってコードに無い)
- `migrations/` のテーブルが、`4-システム.md` の「情報モデル」に無い

条件・状態・BUC のずれは機械では見られない。`reviewer` が見る。
